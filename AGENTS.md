# ARM Agency Site — Agent Handoff

This repository is the production source for **www.arm-agency.com**. It is a static HTML/CSS/JavaScript site deployed through Vercel. It connects a visitor’s Signal Check to a consultative Audit Fit Review and, only after written acceptance, a private collection path.

## Primary files and validation

| Area | Location | Rule |
| --- | --- | --- |
| Main page and offers | `index.html` | Preserve the ordered buyer path and use only the approved engagement names and prices. |
| Signal Check | `audit/index.html` | Keep this a diagnostic and qualification experience. Verify any intake change with owner-controlled data and protect the downstream record. |
| Discovery files | `sitemap.xml`, `robots.txt`, `llms.txt` | Keep canonical public routes aligned with live production. |
| Public resources | `resources/` | Use source-visible, people-first material. Do not extrapolate a third-party system observation into a promised repair outcome. |
| Hosting configuration | `vercel.json` | Do not change production routing or rewrites without direct route verification. |

## Approved offers and claim boundary

The public offer ladder is **ARM Signal Audit ($2,500 fixed scope)**, **Full Signal Repair (private custom scope)**, and **ARM Mandate Pro ($5,000/month)**. Payments remain private and follow written scope acceptance. Do not create public checkout, promise a third-party model answer will change, or represent unverified reputation, governance, or agent outcomes as facts.

The recommended ARM framing is governed agent readiness: a mandate map, decision rights, an evidence/context register, acceptance tests, escalation controls, and controlled change. Terms such as *Truth Ledger*, *Mandate Chain*, *repair*, or *machine-verifiable trust* must be tied to defined artifacts and accepted scope; they are not standalone performance claims.

## Operating controls

No fabricated reviews, ratings, testimonials, client results, sales metrics, or public proof. Keep private lead and test data out of the repository. The Base44 intake endpoint is a record-creation boundary; verify downstream handling only with owner-authorized test identities.

Swell and ARM must share one consultative next step. When editing a CTA, preserve the path **Signal Check → Audit Fit Review → written scope → private collection**, including intended attribution parameters and the fit-review preparation link where relevant.

## Collaboration workflow

Read the relevant page and static assets before editing. Keep copy claim-safe, source-backed, and accessible. After public route or CTA work, inspect the live route directly and record what created a downstream record versus what was view-only. Never add secrets, credentials, raw intake payloads, payment data, or personal prospect information to source control.
